Tests

This page documents each security advisory test currently implemented in ANTA. See the Security Advisory Tests Overview for the support matrix.

Each test’s expected results use the advisory assessment states described in Security Advisory Reports. Standard ANTA test statuses map these states as follows: Not Affected and Mitigated are success, Affected and Inconclusive are failure, and Error is error.

SA225 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0225.

Expected Results
  • Not Affected: EOS or platform is excluded, no affected linecard is installed, or all affected-card interfaces have explicit speed constraints.
  • Affected: Affected EOS and an affected linecard have at least one interface configured with no speed or unbounded speed auto.
  • Error: Required EOS, linecard identity, slot correlation, or speed configuration cannot be determined reliably.
Notes

The affected 750X linecards are CCS-750XM-48TX-LC, CCS-750XPM-48NH-LC, and CCS-750XPM-48TXH-LC. Assessment uses persistent speed configuration, including defaults. Powered-off cards and down interfaces remain in scope; operational bandwidth and link state do not establish safety.

Explicit speed constraints, such as speed auto 1g, remove the exposure prerequisite and produce Not Affected. One validated exposed interface is sufficient despite unrelated incomplete observations; otherwise, relevant inventory and speed evidence must be complete to establish safety.

Remediation recommends a fixed software release rather than assuming the illustrative 1g workaround is suitable for every port. The test assesses exposure, not exploitation or resource-utilization indicators.

Security advisory: Security Advisory 0225

SA224 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0224.

Expected Results
  • Not Affected: EOS or the platform is outside scope, or global PTP is disabled.
  • Affected: An affected 750X platform and EOS release have PTP globally enabled, including when no PTP interfaces are configured.
  • Error: Required EOS, platform, or global PTP state cannot be determined.
Notes

The test does not check whether PTP is enabled on individual interfaces. Global PTP enablement determines the PTP exposure condition; port state, master/slave counts, and traffic counters do not gate the assessment. The test does not detect exploitation.

The operational PTP CPU-queue bandwidth-limiting workaround is not assessed. An in-scope device with global PTP enabled is reported as Affected regardless of workaround application. This conservative coverage limit does not imply that the workaround is ineffective or unobservable. Software remediation lists the fixed releases.

PTP state is read from show ptp revision 2. Explicit disabled mode and the disabled variant containing only an empty interface-summary mapping both establish disabled PTP. Every nonempty mode other than ptpDisabled establishes enabled PTP, including new modes. Missing or malformed required output and empty explicit modes produce Error when required; unsupported or failed PTP collection also produces Error on an otherwise in-scope device. Disabled PTP, excluded software, or an excluded platform can independently establish Not Affected without unrelated unavailable inputs. All required unavailable inputs are retained when no decisive exclusion applies.

Security advisory: Security Advisory 0224

SA223 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0223.

Expected Results
  • Not Affected: For each vulnerability, the EOS version or platform is outside its scope, or its S-BFD setting is not configured.
  • Affected: An affected release on an affected platform has an S-BFD reflector proxy (CVE-2026-121294) or S-BFD initiator round-trip delay measurement (CVE-2026-121295) configured.
  • Error: Required EOS, platform, or S-BFD configuration evidence is missing, cannot be collected, or cannot be interpreted.
Notes

Each vulnerability is assessed and reported separately. CVE-2026-121294 requires a reflector local discriminator with the proxy keyword; a reflector without proxy is not exposed to it. CVE-2026-121295 requires initiator measurement delay round-trip. Either, both, or neither may apply to one device. A configuration line that cannot be interpreted for one setting does not hide established exposure through the other.

Exposure is assessed from the persistent router bfd S-BFD configuration, not from operational state. A configured S-BFD setting is exposed even when no S-BFD session exists or every session is down, because sessions can come up without a configuration change. BFD administrative shutdown is not treated as removing exposure because the advisory does not state that it does.

Platform scope is the advisory’s affected platform list. Platforms outside it, including the listed unaffected AWE 5000, AWE 7200R, 7300X/X3, 7320X, 7358X4, 7368X4, 7388X5, 7130, 7170, 7050X3/X4, 7060X/X2/X4/X5/X6/XE7, and 7260X/X3 families, are Not Affected. Unrecognized or incomplete platform identity produces Error rather than assuming exclusion. An absent S-BFD setting, an out-of-scope release, or an excluded platform independently establishes Not Affected even when other inputs are unavailable.

EOS 4.29 through 4.32 remain in software scope for both vulnerabilities because the advisory lists them as affected without a fixed release; CVE-2026-121294 additionally covers 4.28.2F and later 4.28 releases. The advisory provides no mitigation, so established exposure is Affected and remediation is a software upgrade. The test does not detect exploitation.

Security advisory: Security Advisory 0223

SA222 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0222.

Expected Results
  • Not Affected: The EOS version is outside the affected releases of a vulnerability, or no RPKI cache under router bgp has a configured host.
  • Affected: On an EOS release affected by a vulnerability, at least one RPKI cache under router bgp has a configured host.
  • Error: The EOS version is missing or invalid, the RPKI cache configuration cannot be collected or parsed, or no cache has a validated host while the host configuration of another cache is missing, invalid, or contradictory.
Notes

The two vulnerabilities have different affected releases and are reported separately. Both require one or more configured RPKI caches and an RPKI-to-Router session to the cache.

Exposure is assessed from persistent configuration rather than RPKI session state. A configured cache whose session is down, idle, or not yet established is still affected because the session can be established later without a configuration change. Each cache counts when it has a host, whatever its address family, VRF, port, or transport, including a host name that does not resolve, a VRF that is not configured yet, or a TLS transport without an SSL profile. A cache without a host cannot open a session and does not count. A BGP shutdown does not stop RPKI cache sessions, so it does not make the device safe.

One cache with a validated host is sufficient despite incomplete host evidence for other caches; otherwise, every cache must be interpreted to establish that none has a host. A cache with contradictory host statements is never used as that witness.

The advisory provides no mitigation. Clearing an RPKI cache or restarting the RPKI agent may recover a stuck synchronization state but does not prevent recurrence, so the remediation is a software upgrade. The test does not inspect RPKI counters or logs and does not detect exploitation.

Security advisory: Security Advisory 0222

SA221 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0221.

Expected Results
  • Not Affected: The EOS version is outside the affected releases, no RIP instance is enabled, or no interface with RIP MD5 authentication has an address within a network of an enabled RIP instance in its VRF and none in such a VRF uses DHCP.
  • Affected: On an affected EOS release, an enabled RIP instance has a network that contains the address of an interface with RIP MD5 authentication in the same VRF, or an interface with RIP MD5 authentication uses DHCP in the VRF of an enabled RIP instance.
  • Error: The required EOS version, RIP configuration, RIP authentication configuration, or interface addressing cannot be determined.
Notes

Both vulnerabilities share the same exposure: RIP running with MD5 authentication on an interface. Each is reported separately.

Exposure is assessed from persistent configuration rather than RIP neighbor state, so an interface that is down or currently has no RIP neighbor is still assessed. Every RIP MD5 authentication statement counts, including a key definition without a transmit key and a transmit key with rx-disabled.

An interface with RIP MD5 authentication that uses DHCP in the VRF of an enabled RIP instance is affected regardless of its current lease. The lease can change without a configuration change, so a missing lease or a lease outside the RIP networks does not make the device safe.

Security advisory: Security Advisory 0221

SA220 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0220.

Expected Results
  • Not Affected: The EOS version is outside the affected releases, no RIP instance is enabled, or no enabled RIP instance has a network that contains the address of a management interface in its VRF and no management interface in such a VRF uses DHCP.
  • Affected: On an affected EOS release, an enabled RIP instance has a network that contains the address of a management interface in the same VRF, or a management interface uses DHCP in the VRF of an enabled RIP instance.
  • Error: The required EOS version, RIP configuration, or interface addressing cannot be determined.
Notes

RIP processing on a management interface does not appear in the configuration, so the test correlates the networks of each enabled RIP instance with the primary and secondary addresses of interfaces whose names start with Management. A network matches when it contains the interface address, including a supernet or a narrower prefix.

A management interface that uses DHCP in the VRF of an enabled RIP instance is affected regardless of its current lease. The lease can change without a configuration change, so a missing lease or a lease outside the RIP networks does not make the device safe.

Security advisory: Security Advisory 0220

SA219 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0219.

Expected Results
  • Not Affected: EOS or platform is excluded, no local key controller is configured, or no SA policy enables anti-replay detection.
  • Affected: An affected EOS release and platform have a configured key controller and any SA policy enabling anti-replay detection.
  • Error: Required EOS, platform, controller, or SA policy evidence cannot be determined.
Notes

This test deliberately approximates AutoVPN exposure using a configured key controller and any SA policy with a positive replay window. It favors false positives: an enabled anti-replay policy can trigger an affected result even when it is unused by the controller. No profile binding, dynamic path group, live tunnel, generated keys, or known crypto suite is required. An empty controller JSON root means unconfigured; unknown controller algorithms do not establish absence. Anti-replay configuration is a prerequisite for this issue, not a verified mitigation. A zero replay window excludes that policy without asserting general replay safety; every policy must be disabled to establish absence.

A narrower check would follow the key controller’s configured profile to show ip security profile’s securityAssociation, then inspect that named SA policy’s replayWindowSize. The controller JSON omits its selected profile, so that link would require scoped running configuration. The approximation intentionally avoids collecting running configuration and does not claim to prove that the enabled SA policy is selected.

Bare vEOS model identity is conservatively included because CloudEOS and CVX can share that model string. Explicit vEOS-lab and cEOS-lab identities remain excluded. No live-session state is used to establish that a configured device is not affected.

Security advisory: Security Advisory 0219

SA218 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0218.

Expected Results
  • Not Affected: EOS is outside the affected releases, eAPI is disabled, or management HTTP default services are disabled.
  • Affected: An affected EOS release has eAPI and management HTTP default services enabled.
  • Error: Required software or service-setting evidence is unavailable, incomplete, malformed, or contradictory.
Notes

The test checks configured eAPI and default-service enablement. It does not use listener type, remote reachability, current requests, or transient running state to establish safety. HTTP, HTTPS, local HTTP and Unix-socket choices receive no transport exclusion; this conservative assessment does not claim that exploitation has been verified over every transport.

Disabled eAPI removes an explicit advisory prerequisite even if another management HTTP service remains active. Disabling default services also removes a necessary feature and is Not Affected rather than Mitigated. The default-services setting is read from full-default configuration across both supported carrier contexts; an omitted directive is not treated as disabled.

All EOS platforms are in scope. Exact four-component fixes are honored; earlier 4.x trains without a published fix remain in scope. The test assesses the EOS device itself, including an EOS switch managed by DMF. It does not inspect a DMF controller’s bundled images, read files or logs, send exploit requests, or determine whether exploitation occurred. Remediation recommends fixed software.

Security advisory: Security Advisory 0218

SA217 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0217.

Expected Results
  • Not Affected: EOS or platform is outside scope, 802.1X system authentication control is disabled or unsupported, no interface is configured as an 802.1X authenticator, no DHCP profiling option is configured, or 802.1X accounting does not use RADIUS.
  • Affected: An affected EOS release on an affected platform has 802.1X system authentication control, at least one authenticator interface, at least one DHCP profiling option, and 802.1X RADIUS accounting configured.
  • Error: Required EOS, platform, 802.1X, DHCP profiling, or accounting evidence is missing, invalid, unsupported, or cannot be collected.
Notes

An interface counts as an authenticator when it is configured with dot1x pae authenticator, whatever its configured port-control mode. The advisory sample also configures dot1x port-control auto, but its required conditions only require an authenticator interface, so a force-authorized or force-unauthorized authenticator is conservatively treated as exposed.

Any one of the radius av-pair dhcp hostname, parameter-request-list, or vendor-class-id statements under dot1x satisfies the DHCP profiling condition. The advisory does not require DHCP snooping, so explicit DHCP snooping configuration is not assessed and no ip dhcp snooping does not establish safety.

The default 802.1X accounting list satisfies the RADIUS accounting condition when it contains the built-in radius group or a named group that the device reports as a RADIUS server group, with either a start-stop or a stop-only action. Accounting that only uses logging or a group that is not a configured RADIUS server group does not satisfy it.

Exposure is assessed from persistent configuration. Configured RADIUS servers, server reachability, link state, current supplicants, and authenticated sessions are not required, so an idle or disconnected authenticator does not establish safety.

One valid authenticator interface, recognized DHCP profiling option, or referenced RADIUS group is sufficient despite unrelated incomplete records; otherwise, incomplete evidence produces Error. A command that fails to collect only produces Error when its evidence is needed, so a fixed release, an excluded platform, or an absent condition still produces Not Affected.

The advisory provides no workaround, so established exposure is Affected and remediation is a software upgrade. Platform scope is limited to the listed physical families; virtual EOS, CloudEOS, CloudVision eXchange, 7130, 7170, AWE, and ZTX platforms are not affected. Unrecognized or incomplete platform identity produces Error. The test assesses configuration exposure, not exploitation or the advisory’s RADIUS accounting indicators of compromise.

Security advisory: Security Advisory 0217

SA216 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0216.

Expected Results
  • Not Affected: EOS or hardware is excluded, or no interface has both configured 802.1X (authenticator or supplicant) and an attached MACsec profile using dot1x keys.
  • Affected: Affected EOS and hardware have both configurations on at least one same interface.
  • Error: Required software, hardware, or relevant configuration evidence is unavailable, malformed, or contradictory.
Notes

Assessment uses persistent configuration rather than a currently authenticated session, link state, SSU history, or proof of leaked diagnostic data. Configured authenticators and supplicants are both included. Authenticators require global system authentication control and port-control auto. Supplicants are assessed independently of those authenticator controls and do not require an active session or SSL profile. The test assesses configured exposure rather than exploitation or whether an SSU has occurred.

Profile key sources and interface attachments come from show mac security profile revision 1; authenticators come from show dot1x all revision 1 and supplicants from show dot1x supplicant revision 1. Both role inventories must establish absence before the test concludes that no 802.1X role is configured. An omitted key-source field is the observed unconfigured default, whereas an explicit null or malformed value is an error when relevant. Profiles without interface attachments and configurations on different interfaces do not combine to establish exposure. Cryptographic keys and hashes are not retained as facts.

A complete same-interface match survives unrelated parsing errors; without a match, incomplete relevant evidence prevents a safe result.

The 7388 entry is assessed through the 7388X5 family, and the 7289R3 entry through the 7289R3A family. Existing platform identity groups 720XPM/722XPM separately from excluded 720XP and includes R3A linecards in the 7800R3 family. Virtual EOS platforms remain excluded. Unfixed 4.22 through 4.32 trains are kept open-ended; the named fixed release bounds each later affected train. There is no verified mitigation branch; remediation recommends a fixed software release.

Security advisory: Security Advisory 0216

SA215 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0215.

Expected Results
  • Not Affected: EOS or hardware is outside scope, global system authentication control is disabled, or no auto authenticator is configured.
  • Affected: Affected EOS and hardware have global system authentication control enabled and at least one authenticator in auto mode.
  • Error: Required software, hardware, or controlled-authenticator evidence cannot be determined.
Notes

Requires global system-auth-control and an authenticator port in auto mode. Host mode, VLAN assignment, PBR, and active authentication sessions are not required. Supplicant-only ports do not qualify.

SA214 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0214.

Expected Results
  • Not Affected: BGP is disabled, no VPLS signaling instance is reported, EOS is outside scope, or the platform is outside the R3 scope.
  • Affected: An affected EOS release and R3 platform has BGP enabled and a reported VPLS signaling instance.
  • Error: Required EOS, complete platform identity, BGP state, or VPLS signaling evidence cannot be determined.
Notes

Each CVE is assessed independently. Local signaling instances count even when BGP peers are down or absent. This is a point-in-time operational assessment: successful empty signaling output establishes absence for that observation, including during convergence. Persistent configuration is not checked. Peer state and negotiated labels are not required. Releases before EOS 4.33 are outside both vulnerabilities’ scope. Modular R3 membership is determined from discovered line cards; incomplete chassis identity cannot prove platform exclusion. This test assesses exposure, not exploitation.

Security advisory: Security Advisory 0214

SA213 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0213.

Expected Results
  • Not Affected: EOS is outside scope, no neighbor or peer group is activated in the BGP IPv4 or IPv6 SR-TE address family, or both the configured and operating routing protocol models are ribd.
  • Affected: An affected EOS release has a neighbor or peer group activated in the BGP IPv4 or IPv6 SR-TE address family, and the multi-agent routing protocol model configured or operating.
  • Error: Required software, BGP configuration, or routing-model evidence is unavailable or inconsistent.
Notes

All EOS platforms are in scope. Either SR-TE address family is sufficient; ordinary unicast and other address families do not count. The advisory requires an established neighbor in an SR-TE address family. The test instead checks the BGP running configuration for any neighbor <name> activate under address-family ipv4 sr-te or address-family ipv6 sr-te, globally or in a VRF, because a configured neighbor that is down or not yet negotiated can establish the address family at any time. Neighbor and session state, peer-group membership, and neighbor, VRF, or BGP shutdown are not evaluated.

The routing-model prerequisite is satisfied when either the configured or the operating model is multi-agent, so a model change that awaits a reload does not establish safety in either direction. Without a multi-agent model, an unrecognized or missing value produces Error. The advisory only directs customers to contact support for mitigation guidance, so remediation recommends fixed software.

Security advisory: Security Advisory 0213

SA212 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0212.

Expected Results
  • Not Affected: EOS or platform is outside scope, no BGP-LS peering is configured, or the device reports a non-Pathfinder role.
  • Affected: An affected release on AWE 5000, AWE 7200R, CloudEOS, CVX, or vEOS has enabled BGP-LS activation and the Pathfinder role.
  • Error: Required EOS, platform, configured BGP-LS peering, or role evidence is missing, invalid, unsupported, or cannot be collected.
Notes

BGP-LS exposure is assessed from persistent Link-State address-family presence and neighbor or peer-group activation. A current neighbor, usable dynamic listener, peer ASN, router ID, negotiated capability, or established session is not required. Idle or disconnected sessions do not establish safety. An activated dynamic peer-group remains exposed with zero current neighbors, and an unused activated peer-group is conservatively treated as exposed because the test does not require proof of current group membership or a usable listener.

Verified persistent BGP process, VRF, Link-State address-family, or neighbor shutdown establishes absence of the disabled exposure. Peer-group shutdown is inherited unless an explicit neighbor no-shutdown overrides it. An enabled member inheriting activation keeps its group exposed; explicit AF deactivation closes that member path. Whole-process, VRF, and AF shutdown still disable their entire scope. Unresolved inheritance cycles are conservatively treated as enabled rather than proving safety. At least one enabled activation in any configured instance and VRF is sufficient; shutdown settings and other address families do not leak across sibling scopes. Global peer-group shutdown is considered for VRF members. A locally redeclared group is conservatively treated as independent of its namesake.

The reported AVT role is device-wide and does not require live paths or a working BGP session. The test does not add a BGP-LS DPS consumer-role prerequisite. Operational summaries are not collected, so unrelated incomplete peer or VRF records cannot veto established configuration exposure. Missing, malformed, unsupported, or failed persistent configuration evidence produces Error when needed.

Successfully reported edge, zone transit, region transit, and unknown roles establish that the Pathfinder prerequisite is absent. A missing role, unrecognized role, or AVT command error (including an unconfigured AVT agent) is unavailable evidence and produces Error when role evidence is needed; it is never replaced with the valid unknown role. No configured BGP-LS peering, an excluded platform, or a fixed release independently establishes Not Affected even when other inputs are unavailable. Otherwise all required unavailable inputs are reported together.

Platform scope includes AWE 5000, AWE 7200R, CloudEOS, CVX, and vEOS identities. CVX and vEOS identities are included conservatively because the raw vEOS model can represent CloudEOS. Ordinary cEOS-lab and vEOS-lab are excluded even if they accept the commands. Unrecognized or incomplete platform identity produces Error rather than assuming exclusion. All 4.32 and older EOS 4 trains remain in software scope because the advisory lists them as affected without a fixed release; later trains use the named fixed boundaries.

The advisory provides no complete configuration mitigation, so established exposure is Affected and remediation is a software upgrade. The test assesses configuration exposure, not exploitation or the advisory’s path-change indicators of compromise.

Security advisory: Security Advisory 0212

SA211 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0211.

Expected Results
  • Not Affected: EOS is outside scope, or configured Link-State peering with the DPS consumer role is absent.
  • Affected: An affected EOS release has persistent Link-State activation and the DPS consumer role in the same BGP instance and VRF.
  • Error: Required software, configured peering, processing role, or scope identity evidence is unavailable or inconsistent.
Notes

Persistent Link-State activation remains exposure while sessions are idle, down, or disconnected. Activated unused peer groups and dynamic listeners without instantiated peers are conservatively included. Confirmed persistent administrative shutdown of the BGP instance, VRF, Link-State address family, or every activated neighbor/group establishes absence of exposure. Session establishment, negotiated capabilities, route counts, and observed attack traffic do not establish configured absence. Pathfinder and transport authentication are not additional prerequisites for this assessment.

Link-State activation and the DPS consumer role are correlated by configured BGP instance and VRF. Numeric and asdot local-AS forms are compared by their ASN value; missing, malformed, or mismatched instance evidence produces Error. Operational router IDs, runtime peer inventories, and remote peer ASNs are not required. A consumer role in one instance or VRF is not combined with activation from another. The processing-role command uses structured role and protocol values; other consumer protocols and a propagator-only role do not satisfy the DPS consumer requirement. Valid empty role lists or an empty Link-State family object establish that the role is absent, while missing or malformed required role evidence produces Error.

Persistent BGP configuration supplies the activation and administrative-state evidence. Absence of administratively enabled Link-State activation establishes Not Affected independently of failed role collection. An activated scope missing from structured role output, or an explicit configured consumer contradicted by that output, produces Error. The test does not collect a runtime peer summary.

A fixed release or decisive feature absence independently establishes Not Affected even if unrelated inputs are unavailable. Otherwise all required unavailable facts are retained. All EOS platforms are in scope without a platform allowlist. EOS 4.32 and earlier EOS 4 trains remain in software scope without a named fix; subsequent trains use their named fixed release boundaries.

No complete configuration mitigation is available. Established exposure is Affected with fixed software as remediation. The test assesses configured exposure and does not determine whether exploitation has occurred.

Security advisory: Security Advisory 0211

SA210 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0210.

Expected Results
  • Not Affected: EOS is outside scope, or no neighbor or peer group is activated in the BGP path-selection address family.
  • Affected: An affected EOS release has a neighbor or peer group activated in the BGP path-selection address family.
  • Error: Required software or BGP configuration evidence is unavailable.
Notes

All EOS platforms are in scope. The advisory describes exposure through an established session with the path-selection address family negotiated. The test instead checks the BGP running configuration for any neighbor <name> activate under address-family path-selection, because a configured peer that is down or not yet negotiated can establish the address family at any time. Neighbor and session state, peer-group membership, and neighbor, VRF, or BGP shutdown are not evaluated. The routing protocol model is not a prerequisite. The advisory provides no mitigation, so remediation recommends fixed software.

Security advisory: Security Advisory 0210

SA209 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0209.

Expected Results

Notes

All EOS platforms are in scope. Listen ports are read from the bgpIpv4ListenPort and bgpIpv6ListenPort values of every VRF in show bgp instance vrf all. The routing-model prerequisite is satisfied when either the configured or the operating model is multi-agent, so a model change that awaits a reload does not establish safety in either direction. Without a multi-agent model, an unrecognized or missing value produces Error.

The advisory’s custom control-plane ACL alternative depends on operator-specific expected peers and TTL values that the device cannot validate, so ACL configuration never produces Mitigated or Inconclusive. SA117 ¶

Preview

Input models and behavior may change between minor releases without a deprecation notice.

Verify whether the device is impacted by Security Advisory 0117.

Expected Results
  • Not Affected: EOS is outside scope or no gNMI transport is enabled.
  • Inconclusive: An affected EOS release has gNMI enabled, but the gNOI File service and effective gNSI Authz controls cannot be evaluated.
  • Error: Required EOS or gNMI state cannot be determined.
Notes

Exposure remains inconclusive because disabling the gNOI File service and an effective gNSI Authz policy that blocks TransferToRemote cannot currently be evaluated with trusted narrow EOS evidence.

The advisory requires gNMI accounting or an advisory-identified OpenConfig trace selector. This test does not use OpenConfig trace state: an operator can enable the trace at any time with start trace, which leaves no running-config record and disappears from show trace OpenConfig once the timer expires, so trace state cannot rule out exposure. Because the trace branch cannot be excluded, accounting state cannot change the result either.

Security advisory: Security Advisory 0117
